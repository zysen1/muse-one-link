# 发给 Muse 的复刻提示词

复制下面整段，连同本仓库链接发给 Muse。它是一次搭建请求；搭完后能否从页面一键操作平台，需要按实际能力验收。

```text
请按这个仓库的外卖买菜案例，为我搭一个可反复使用的“外卖买菜优选”构件：
https://github.com/zysen1/muse-one-link/tree/main/cases/grocery

先读该案例 README.md、仓库 AGENTS.md 和 docs/BUILD.md，实际完成工具与测试，不要只给方案。

我想少花时间翻几个 App、算红包。请保存我的口味、忌口、人数、总预算、最晚送达时间和常用平台偏好；已有信息直接沿用，没给的个人信息不要编。实际地址、账号和订单仅保存在私人工作区或平台会话，不放进公共仓库。界面先做好，缺少关键条件时只问必要的一项。

每次默认比较 2–3 个我当前能用的平台；如果我指定平台，就按指定范围。读取真实商品、规格、份数、配送时间和这个账号可用的优惠，核对门槛、适用商品、有效期、叠加或互斥、会员是否需要新付费。把包装费、配送费等必付费用算入总价，以结算页核对结果为准；只有标价就标“估算，结算待核对”。不要自动买券、开会员或把未来返券当本单立减。

先过滤忌口、预算、份量、配送范围和时限等硬条件，再从本次已核对的候选中给“价格优先、口味优先、最快送达”三个选择，附总价拆分、优惠依据、预计时间、来源入口和核对时间。凑单要比较最后实付，不能多买更贵还叫省钱。没有合格候选就说明原因，不承诺全网最低或人人同价。偏好改了要重新排序，准备订单前再查价格、库存、优惠和配送。

请接好真实 Muse 动作或后台，让“刷新候选、重新推荐、准备购物车”能执行并显示真实状态。先查看当前可用接口的说明，不猜内部 API。如果只能复制提示词，按钮就叫“复制指令”，别说已经一键接通。未登录时继续完成偏好保存和样例计算，明确显示“演示数据，未读取真实平台”；用 examples/meal-choice.json 做解释示例，不把样例当实时商家结果。登录验证交给我在官方界面完成。

默认到购物车或待确认订单，不提交、不付款。修改购物车须在我明确授权的商家、商品和操作范围内；无授权只读，不动既有车或无关商品。已有授权不用重复问。若我明确要求提交订单，先核对商家、订单内容、预算和范围，只按该授权及平台权限处理，不扩展成付款。重复点击、超时和重试前先查原任务与实际购物车，避免重复加购或提交。

可选保留“菜单与库存补货”，使用 examples/grocery.json，按需求减库存计算缺口，区分食材数量与商品包装，不因清单重算就改真实购物车。

请验证：优惠不适用、券互斥、凑单反而更贵、超过配送时限、修改偏好后重排、重复点击不重复加购，以及刷新后偏好仍在。样例测试与真实平台测试分开；有登录和操作授权时核对真实结算价与购物车结果。未接通的平台明确列出，不能用假结果补成功。

最后给我可用入口、一句话操作方法、私有数据保存位置、启动恢复方式和已完成/待接入清单。只有按钮真实接通且验收成功，才把对应功能标成“一键使用”。
```
