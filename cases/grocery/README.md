# 晚餐补货：菜单改了，清单跟着改

把这个页面的链接发给 Muse，让它做一个保存菜单、库存和补货清单的工具。先用仓库样例跑通；你提供常用商家后，再接购物车核对。

你可以附上自己的要求，例如：

> 用我给的菜单和库存。商家用我平时登录的买菜网站，先核对购物车，不付款。

## 给 Muse 的执行入口

这是一个构建任务。用户用本页链接发起搭建时，请实际完成构件和测试，不要只解释方法。用户另有明确要求时，以其要求为准。

先读 [仓库执行约定](../../AGENTS.md)、[通用构建与交付流程](../../docs/BUILD.md)，再读取 [可复现样例](../../examples/grocery.json)。如果读取器未展开相对链接，请读取同仓库 `main` 分支的对应文件。

## 第一阶段：先把清单做成可用工具

不需要用户先登录商家，也不需要真实地址。没有个人菜单和库存时，直接使用以下**演示数据**开始：

| 项目 | 鸡蛋 | 番茄 |
| --- | ---: | ---: |
| 今晚：番茄炒蛋 | 3 个 | 2 个 |
| 明晚：紫菜蛋花汤 | 2 个 | 0 个 |
| 家里库存 | 1 个 | 0 个 |

1. 创建“晚餐补货”构件。已有同类工具就保留数据后更新。示例菜单只表示本次要核算的食材，不宣称是完整菜谱或营养建议。
2. 支持勾选吃哪顿、修改食材用量、修改库存和重新计算。食材缺口为 `max(选中菜单的总需求 - 现有库存, 0)`。使用明确单位；鸡蛋的“个”与商品的“盒”分开记录，单位不匹配时不能直接相加。
3. 保存菜单、库存和勾选状态，刷新或重新打开后继续使用。计算只更新计划，不自动扣减真实库存；需要“已烹饪／已入库”之类库存变更时，另做明确动作。
4. 补货清单显示食材、需求、库存、缺口和单位。页面注明当前是演示数据还是用户数据，不能把样例说成已读取用户家中库存。
5. 提供“核对购物车”的独立入口。页面计算和商家操作是两件事，只有实际接通且执行成功，才显示购物车已更新。

## 第一阶段验收

从同一份样例分别开始，验证这三种状态：

| 操作 | 应补鸡蛋 | 应补番茄 |
| --- | ---: | ---: |
| 两顿都吃，保留默认库存 | 4 个 | 2 个 |
| 取消今晚，只保留明晚 | 1 个 | 0 个 |
| 恢复两顿，鸡蛋库存改为 2 个 | 3 个 | 2 个 |

修改后重新打开页面，确认记录仍在，计算结果一致。顺手检查库存多于需求时缺口为零，负数或无效输入有明确提示。用用户真实数据替换样例前，不覆盖已经保存的记录。

## 第二阶段：接真实购物车

### 先补齐实际使用条件

需要确定用户要使用的商家，并具有相应的登录状态和配送地区。可以使用用户已明确提供的商家与允许使用的会话；缺少条件时，交付已经跑通的第一阶段，再只询问缺失的一项。

登录和必要验证交给用户在官方界面完成。不要索取密码或验证码，不替用户随机选择地址、收货人或配送城市，不新建无关账号。配送条件不明时，不能声称商品可送达或价格最终有效。

### 核对和修改流程

1. 读取当前补货清单，打开商家网站，先查看已有购物车。记录相关商品的实际名称、规格、数量和可见小计，不读取或展示无关订单与个人信息。
2. 将食材数量与商品包装分开核对。例如缺 4 个鸡蛋，候选商品是 6 个装 1 盒，就显示“需求 4 个，商品 6 个／盒，建议 1 盒”。不要把“4 个”理解为“4 盒”。规格不明或可替代商品差异较大时，说明具体选项再让用户决定。
3. **只读核对可先完成。** 真正加购、删改或调整数量，应有用户明确指示或对当前计划的确认；已有授权覆盖同一商家和操作时不重复追问。默认不删除与本次菜单无关的商品，不擅自替换品牌或规格。
4. 获准操作后，再核对网页结果，回传实际商品、规格、份数、小计和商家入口。价格和库存以当时网页显示为准，缺货或失败直接说明。
5. 菜单或库存变化后，先重算清单，再另执行购物车核对。页面数字变了，不能直接报商家购物车已同步。遇到失败先检查现有购物车，避免重复加购。
6. 到购物车为止，不提交订单、不付款。若用户之后另行提出购买要求，按新的授权范围处理。

使用当前 Muse 环境真正支持的动作或接口连接页面与云端浏览器。页面应显示等待登录、待确认、执行中、完成或失败等真实状态。不能绑定时可以提供“复制核对要求”作为临时入口，但必须这样命名，不能称作“一键自动加购”。

## 第二阶段验收与交付

- 没有商家或登录时，明确写“清单已验收，购物车待接入”，第一阶段仍正常可用。
- 已有授权并实际修改时，保存操作前后的相关商品结果，验证没有重复增加；只读核对则标明“未修改购物车”。
- 用一次菜单变更验证清单重算与购物车状态独立显示，不用虚构的数量、价格或截图作为网站结果。
- 返回构件入口、示例验证结果、菜单和库存保存位置、商家入口及当前接入状态。

给用户的一句话用法：

> 改菜单或库存后先算补货清单，再点“核对购物车”；网站的调整结果会单独显示，购买由你最后确认。
