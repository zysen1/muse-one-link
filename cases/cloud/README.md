# 免费云环境与资源工具箱

让 Muse 帮你找适合项目的免费云资源，协助申请，再把项目部署成能打开的工具。

**使用方法：把本页链接发给 Muse。** 有想部署的项目，就一起发项目链接或用途；没有也可以，默认先做一个个人便签工具。

## 给 Muse 的执行入口

用户将本页作为搭建任务交给你时，请先读 [仓库执行说明](../../AGENTS.md) 和 [构件搭建约定](../../docs/BUILD.md)，然后按下面的流程执行。交付实际工具与验证结果，不止总结本页或列出候选平台。继续遵循当前会话的用户要求与权限。

### 1. 用已有信息开始

| 项目 | 默认选择 |
| --- | --- |
| 要做什么 | 用户给的项目优先；未提供时做“我的便签” |
| 便签功能 | 新增便签、编辑、按标签筛选、保存后重新打开 |
| 演示内容 | 自行写两条不含个人信息的示例便签 |
| 界面 | 中文、手机与电脑都能操作 |
| 预算 | 先用符合条件的免费方案；不新开付费计划、不绑卡 |
| 第一阶段 | 在 Muse 云电脑上做出可运行版本，再落实外部环境 |

不要为了名称、配色或技术栈先问一串问题。根据已有运行环境选一个简单方案，说明采用的默认值并继续。

如果用户提供了项目，先读它的 README、许可证、部署文档和依赖，确认它需要完整服务器、静态网站托管、数据库还是其他运行环境。不要把静态托管当成能运行任意后台程序的服务器。

### 2. 先做出可运行的小版本

在独立目录保存源码与数据，保留已有文件。默认便签工具可用当前环境已有的 Node.js 或 Python，选择带持久化存储的简单实现。

将页面接到真实的数据读写：新增便签后能在列表看到，编辑后能保存，标签能筛选，刷新或重新打开后记录仍在。优先使用现有构件能力提供入口；需要后台程序时，接通真实动作与状态反馈。

此时可以交付“在 Muse 环境内已可用”。仅有本机端口、页面预览或启动日志时，不把它叫作对外访问成功。

### 3. 筛选免费云资源

优先查看当前账号已有且已授权使用的资源，再筛选最多两到三个适合项目的候选。先从 [官方入口清单](../../docs/RESOURCE_SOURCES.md) 找资料，也可以补充更合适的服务。

每个候选记录以下内容，并保存官方链接和核对日期：

- 项目所需的运行时、存储、网络是否支持。
- 免费额度、有效期、休眠或回收规则。
- 是否需要登录、身份验证、银行卡或其他资格。
- 超出额度后的行为，是否会产生费用，以及如何停止或释放资源。
- 当前用户的地区与账号是否适用，能否提供所需的访问入口。

根据实际项目选一个继续，不只交一张比较表。没有可确认的合适免费方案，就说明具体原因，保留已做好的 Muse 内版本。

### 4. 协助申请并继续部署

先完成能够在现有授权内完成的准备工作。遇到必须本人完成的登录、身份验证或条款确认，给用户准确的页面和这一项操作；不要索取密码或验证码，不代填虚假身份。用户完成后，从原进度继续。

外部资源实际开通后，再安装依赖、配置程序、迁入演示数据并启动服务。只使用平台正式支持且当前授权允许的部署与访问方法，不为“免费”改变安全设置或规避额度限制。

记录程序实际运行在哪里：Muse 云电脑、外部开发环境或正式托管服务。临时开发环境可以用来测试，不把有停止规则的环境宣传成永久在线服务器。

登录或申请卡住时，继续完善本地工具、部署文件、测试和操作说明。不得用本机运行结果证明外部机器已运行。

### 5. 做好入口与服务面板

把已可用的工具整理进一个中文面板，至少显示：名称、用途、真实入口、部署位置、当前状态和已知有效期。

本人入口与对外分享入口分开处理。需要给其他人使用时，按用户要求配置相应权限，避免将私人便签直接公开。没有通过访问测试的地址标为“待验证”，不要放一个看似可用的假按钮。

### 6. 实际验收再交付

至少完成这些检查：

1. 新增一条示例便签，确认保存成功。
2. 刷新页面，确认同一记录仍在；修改内容后再次打开核对。
3. 按标签筛选，再清除筛选，确认数据正确。
4. 在没有进行中的任务时，按当前环境允许的方式重启应用，核对保存的数据。
5. 外部部署完成后，从实际使用入口访问并重复一次新增、刷新检查；无法操作其他设备时，明确该设备尚未验证。

交付简明结果：

```text
工具名称与用途：
Muse 内可用入口：
外部服务入口：可用地址 / 未开通 / 待验证
源码与数据位置：
已验证：本地运行 / 资源创建 / 外部部署 / 外部访问
免费额度、有效期和停止方式：
还需要用户完成的一步：无 / 具体操作
```

附上必要的结果截图和源码备份。不要在截图、日志或公开仓库中放账号凭据、支付信息或私人数据。申请成功、服务启动和外部访问成功是不同结果，分别说明。

## 可选：把找到的资源做成工具

这些是用户提出相应用途时再执行的扩展，不默认同时开启全部任务。

### 免费素材库

从官方来源少量下载所需图标、音效、字体或纹理；保留来源、许可与文件位置，再做成可搜索、图片可预览、音频可试听的页面。逐个验证文件能打开。免费使用不等于允许整包公开再分发，分享时按各自许可处理。

### 开源音频处理

优先使用云电脑已有的 FFmpeg，先用自己生成的两段示例音频验证转格式、按顺序拼接与输出试听。保留原始文件，结果另存。随后再接上传、排序和下载入口，用实际上传文件复测；固定样例成功不代表任意文件流程已经完成。

如果构件的下载按钮未生效，先通过当前环境支持的附件交付真实文件，说明限制，再修复并验证下载入口。

## 完成后怎么继续用

用户可以直接说：“把这个新项目也加进去”“给这个工具换一个合适的免费环境”或“把素材处理再加一个按钮”。复用已有面板和记录，先检查现有服务状态，不重复申请同一资源。
