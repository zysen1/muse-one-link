# 发给 Muse：搭一个免费开发云电脑

把本页链接发给 Muse，再补一句：**“请按这里帮我搭好，并实际打开网页验证。”** 以下是完整执行任务。

---

请使用我的 GitHub 账号，在有可用免费额度且不新增付费的前提下，复刻这个 **Codespaces + 中文口播计时器**。先读取本案例 [README](README.md)、[仓库执行说明](../../../AGENTS.md) 和 [通用搭建流程](../../../docs/BUILD.md)，然后完成部署，不只给我一份方案。

1. **核对条件。** 打开 GitHub Codespaces 与 Billing，核对个人计划、剩余计算/存储额度、超额预算及已有实例。需要登录或验证码时，让我在可见页面亲自完成，不要索取密码、验证码或令牌。不要绑卡、充值、升级套餐、提高预算或批量申请账号。
2. **复用或创建一个实例。** 优先复用适合本任务的已有 Codespace；没有时，从 [本仓库创建入口](https://codespaces.new/zysen1/muse-one-link?quickstart=1)创建最小可用的 2 核实例。仓库 devcontainer 配置为使用 Python 3.12、自动启动应用并转发 8000；该新配置尚未在全新实例端到端验收，需要你检查实际结果。遇到额度不足或付费门槛，说明具体缺项，保留已准备的源码，不冒充开通成功。
3. **使用实际源码。** 仓库地址是 `https://github.com/zysen1/muse-one-link`。如果在已有 Blank 实例内，先克隆到独立目录；已有同名目录先检查，不覆盖用户数据。主程序是 `cases/cloud/codespaces/app.py`，只使用 Python 标准库。进入仓库根目录后，用以下命令管理，不重复启动已有服务：

```bash
python3 cases/cloud/codespaces/start.py status
python3 cases/cloud/codespaces/start.py start
```

4. **验证真实云端。** 在云端请求 `http://127.0.0.1:8000/api/status`，核对真实 Linux、Python、可见逻辑 CPU 和 UTC。不要写死返回值，也不把你的本机结果当作 Codespaces 结果。
5. **打开私有网页。** 在 Ports 确认 8000 为 **Private**，打开预览；缺少转发时手动添加 8000，仍保持 Private。不要把整个工具或用户文案公开到公网。页面能打开后，实际点击按钮验证 `POST /api/analyze` 的结果。
6. **至少做两次输入测试。** 语速都设为 240 字/分钟：`你好，Muse！` 应为 **8 字、2 秒**；下面两行应为 **7 字、1.75 秒**，第一行中间有空格：

```text
你 好
Muse！
```

再换一段我自己的口播稿，确认结果随输入变化。空白不计、标点计入；这是语速估时，不是语音生成。

7. **失败时继续处理现有实例。** 若 VS Code 浏览器端连接失败，记录具体错误。已有实例预装 JupyterLab 时，按官方方法尝试实例菜单 **Open in → JupyterLab**，在 Terminal 运行相同命令；本仓库的 Python 镜像不保证提供它。不要为了重试反复创建机器或擅自改我的代理/路由。Jupyter 终端成功不等于私有网页已验证，Notebook/widget 也不是本任务必需项。
8. **交付真实结果。** 给我自己的私有预览入口、源码目录、实际 API 环境、两次计算结果、Private 端口截图和停止/恢复方法。截图去掉账号资料、私有地址和凭据后才能公开；不要把仓库作者的旧截图当成这次已完成的证据。

交付时准确说明操作发生在哪里、由哪个工具完成。本仓库示例是 Codex 在本机浏览器操作的已成功实测，**不是你的 Muse 已完成自动申请**；你需要重新验收自己的执行结果。

让我试用时可以保留正在运行的实例，并告知正在消耗计算额度；使用结束在 Codespaces 控制台 **Stop codespace**。只运行下方命令会停止应用，不会停止云电脑计时：

```bash
python3 cases/cloud/codespaces/start.py stop
```

恢复原实例后先检查状态，必要时再次 `start`。说明保留磁盘仍累计存储用量，不承诺永久免费或 24 小时在线。额度、登录、网络或预览仍有缺项时，把已完成与待完成分开交付。
