# 今日精选：让 Muse 先替你筛内容

把这个页面的链接发给 Muse，让它做一个能保存来源、按目标挑内容、反复打开的“今日精选”。你也可以在链接后补一句自己的需求，例如：

> 我想学手机摄影，优先找能跟着拍的教程。

不补充需求也能开始：默认寻找**解决 AI 视频人物跨镜头不一致问题的公开教程**，先给出 3 条可操作的精选。

## 给 Muse 的执行入口

这是一个构建任务。用户用本页链接发起搭建时，请按下面的流程完成工具和测试，不要只总结本页或交付一份计划。用户另有明确要求时，以其要求为准。

先读 [仓库执行约定](../../AGENTS.md) 和 [通用构建与交付流程](../../docs/BUILD.md)。如果链接读取器未展开相对链接，读取同仓库 `main` 分支的这两个文件，再继续本案例。

## 先做出能用的版本

1. **确定默认输入。** 名称用“我的今日精选”；目标用“找到能解决 AI 视频人物跨镜头变脸的具体方法”；结果数量为 3。已有同类构件就保留数据后更新，不重复创建。用户没有指定来源时，从可访问的作者原文、官方教程、公开博客及视频字幕开始，不先追问一串偏好。
2. **真实读取内容。** 使用当前环境可用的搜索、浏览器或连接器找候选。优先包含步骤、参数、示例或对比的内容。需要登录的来源先标出，继续处理公开来源。打不开的网页不得凭标题补出“正文总结”。
3. **留下可追溯的卡片。** 每条至少包含标题、作者或发布者、原始链接、获取时间、实际读取的证据类型、简短摘要、能解决哪个问题，以及一项可以尝试的操作。证据类型区分“正文”“视频字幕”“视频画面与字幕”“仅摘要”；只有字幕时不得声称已看完视频画面。发布日期查不到就注明未知，不猜测。
4. **保存并去重。** 将来源设置、当前目标、候选、精选、已读记录与反馈保存在用户工作区的持久数据中。按规范化链接和内容去重；不要每次覆盖用户的来源和历史。摘要保持简短，保存原始链接便于回看。
5. **做成构件。** 页面提供“修改目标”“搜集新内容”“用现有内容重新筛选”“已读”“有用／少推”以及原文入口。当前目标、最近更新时间和运行状态应一眼可见。
6. **接上真正执行的动作。** “搜集新内容”应调用已接通的云端流程并将真实结果写回；“重新筛选”使用已保存的候选。检查当前 Muse 支持的构件动作和接口，用实际文档及能力接入，不猜接口。暂时无法绑定时，仍完成可用的保存与筛选功能，并明确标记搜集入口未接通；复制一段指令的按钮只能叫“复制搜集要求”。

筛选时同时考虑：是否切合当前问题、步骤能否照做、来源可靠性、信息是否重复以及用户反馈。不要把点赞量当作唯一标准，也不要根据用户喜好篡改原文结论。

## 用真实数据验收

- 搜集并打开至少 3 条真实内容，卡片的原链接和证据类型能对应到实际读取结果。公开来源不足 3 条时交付实际数量和缺项，不编造补齐。
- 将目标从“解决人物跨镜头不一致”改为“了解 AI 短片从分镜到剪辑的完整流程”，对**同一批候选**重新筛选，展示两次排序及理由。若候选不足以体现区别，补充真实相关候选后重测，不硬编码一个看似改变的排序。
- 点一次“已读”和一次反馈，重新打开构件，确认目标、记录和反馈保留。
- “搜集新内容”若已接通，实际执行一次并核对更新时间、任务状态和新写入内容；失败时显示具体原因，不能仅显示成功提示。
- 检查手机宽度下卡片可读、按钮可点。跨设备登录和第三人共享属于独立验证，按通用交付流程报告。

## 跑通后再加的功能

只有用户明确提出时间、接收位置或发布要求时，再配置定时更新、外部通知或内容分发；本案例默认不创建定时任务，也不向其他人发消息。

可以先加“生成待发草稿”：用户选择一条资料并补充观点后，整理成短帖、长文提纲或视频选题，保留来源，保存到待发布区。采集平台和发布平台逐个接入、逐个验证；实际发帖需要用户对内容及目标平台的明确授权。

## 交付给用户

返回可重新打开的构件入口、3 条实际精选、修改目标的方式、数据保存位置，以及尚未接通的动作。用一句话说明使用方法，例如：

> 改一下今天想解决的问题，点“用现有内容重新筛选”；要读新资料时点“搜集新内容”。

如果某个按钮尚不可用，直接说清楚停在哪一步。目标是交付可反复使用的工具和真实内容。
