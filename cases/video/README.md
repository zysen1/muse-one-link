# 连贯短片与抽卡工作台

把短片分段生成，用前一段的实际画面续接后一段；不满意的镜头继续补候选，满意的保留，最后导出完整视频。

**把这个页面的链接发给 Muse 即可开始。** 没有补充需求时，先按下面的默认项目搭建。想换题材，在链接后补一句，例如：“换成雨天咖啡馆，做 20 秒竖屏。”

> Muse：这是搭建任务的执行入口。读取 [仓库说明](../../AGENTS.md) 和 [通用搭建流程](../../docs/BUILD.md)，按本文完成环境检查、构件实现与可执行的验收，交付实际入口；不要只总结本文。

## 先做出什么

一个能重新打开的视频工作台，保存项目、分镜、参考图、所有候选和选片记录，提供这些操作：

- 修改题材、目标时长和画幅，查看分镜与预计生成数量。
- 逐段生成、查看候选、选择版本、给指定镜头“补一条”。
- 检查更换上游镜头后，哪些后续镜头需要重新衔接。
- 预览并导出真实 MP4，保留项目和源素材，之后接着做。

## 默认项目

| 项目 | 默认值 |
| --- | --- |
| 题材 | 街边早餐摊：摊主装好早餐，轻推纸袋，顾客取走 |
| 风格 | 自然日光、普通成年人物、日常随拍，动作简单 |
| 目标 | 30 秒，9:16 竖屏；可另剪 20 秒精简版 |
| 首轮生成 | 最多 3 段、每段 1 个候选；不自动补抽 |
| 工作位置 | Muse 云电脑；构件是操作入口 |

[项目样例](../../examples/video-project.json) 是待执行的计划，里面没有生成结果。单段时长必须按当前账号和工具实际能力调整，不能把“10 秒”写死成所有环境的上限。若完成目标需要超过首轮数量，先交付已完成的小样和明确的追加计划。

## 给 Muse 的执行步骤

### 1. 检查环境，建立项目

1. 检查实际可调用的视频生成工具、支持的时长、画幅、参考图或续接能力，以及文件交付方式。先读当前工具文档或帮助，不猜测命令、端点或参数。
2. 复用已有同名工作台；没有就创建。给新项目使用独立目录，保留已有文件。用户没指定的题材细节用上述默认值，不逐项追问。
3. 先接好项目保存、候选列表和任务状态。使用当前 Muse 环境支持的构件与云端动作机制；按钮必须绑定真实动作。若某个动作不能接通，显示具体缺项，并继续完成可用部分。
4. 生成会消耗账号额度。使用本次任务已有的授权和平台权限；确实缺少必要授权时，先完成不耗额度的搭建，再说明一次小样的数量。发送链接不代表同意无限生成、新增付费服务或自动充值。

### 2. 先规划衔接，再逐段生成

1. 固定人物外观、服装、场景、道具、光线和机位关系。把每段的起始动作、结束状态、镜头运动写入分镜。
2. 选用当前工具支持的分段时长。若支持每段 10 秒，30 秒目标可规划成 3 段；实际结果时长以文件检测为准。
3. 先生成并检查第一段，再从选中视频提取适合续接的实际结尾画面。把它和固定的人物、场景参考，按当前工具支持的方式用于下一段。
4. 若工具不支持参考帧或原生续接，明确说明；可以在支持的范围内采用同一参考图和较简单的固定机位方案，不声称使用了不存在的续帧功能。
5. 一段完成后再安排依赖它的下一段。记录任务 ID、候选 ID、使用的上游候选和参考帧，不盲目并行依赖镜头。

### 3. 让补抽和选片可持续使用

每个镜头都保留候选及其提示词、参考图、实际时长和文件位置，不覆盖旧版本。“补一条”只提交当前镜头的一个新候选；进行中的同一请求应禁用重复提交。超时先查已有任务，不把刷新页面或重复点击变成再次生成。

选择新的上游候选时，检查引用旧候选或旧尾帧的后续镜头，将它们标为“需要重新检查衔接”。保留原文件，先检查接点，再决定是否重做；需要补生成时显示镜头和数量，不静默重跑整条。

用户可以一轮轮追加候选并选择。“反复抽卡”仍受账号额度、平台能力和用户决定的数量限制；不要创建无限重试循环。

### 4. 检查画面，剪成真实成片

- 正常速度观看，并在每个接点抽帧检查人物、手、服装、道具形状、位置、视角和运动方向。
- 优先简化明显容易失真的动作。例如纸袋被折成扁纸包时，可改成轻推完整纸袋，再用新片段续接。
- 在云电脑上用实际可用的剪辑工具合成，修剪多余停顿，合理处理环境声。20 秒精简版按动作剪裁，不靠整体加速凑时长。
- 检测 MP4 的实际时长、画幅和音轨，并打开播放；交付真正的视频文件，不用静态图、测试色板或旧视频代替新生成结果。
- 将实际生成和剪辑结果写回工作台。下载按钮与聊天附件要分别验证，不能把附件可下载说成页面按钮已经可用。

## 验收后再交付

| 要检查的事 | 通过标准 |
| --- | --- |
| 项目保存 | 重新打开后，分镜、候选与选片仍在 |
| 生成与状态 | 任务真实提交、状态更新，候选对应实际文件；没生成的项保持未完成 |
| 衔接依据 | 下一段能追溯使用了哪个上游候选和参考；更换上游能识别受影响镜头 |
| 补抽 | 在已授权的额外生成中实测一次；未授权时只完成实现并明确尚未实测，不额外花额度 |
| 成片 | MP4 能播放，报告实际时长和画幅，说明仍可见的跳变 |
| 交付 | 实际构件入口、源项目、成片文件和一句使用方法；成功与缺项分开写 |

不要把“程序启动了”“界面能打开”“确实生成了视频”“手机电脑都能访问”合并成一个成功状态。按实际检查结果说明即可。

## 可选：接成 API，供其他软件调用

原构件流程可先独立完成。用户还希望从 Claude、Codex 或其他客户端调用时，再使用 [SenMuse](https://github.com/zysen1/senmuse)：

1. 读取 [SenMuse 的 AGENTS.md](https://github.com/zysen1/senmuse/blob/main/AGENTS.md) 与 [AI 部署指南](https://github.com/zysen1/senmuse/blob/main/docs/AI_DEPLOYMENT.md)，按真实环境部署。
2. 分别确认云内可调用、目标客户端可连接、真实视频生成和下载；服务器本地健康检查不能代替外部访问验证。
3. 接好工作台到服务的提交、状态和结果写回。保留鉴权，明确入口的实际有效期，不把公开配置地址当作已具备公网连接。
4. 外部客户端不可访问时，交付已完成部分和客户端检查方法，标记外部链路未验证。

一个可用的 Muse 原生工作台，并不自动证明外部 API 已经接通。
