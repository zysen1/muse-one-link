# 通用搭建流程

这是各案例的共同实施路径。目标是交付可反复使用的工具，让用户以后改输入、点按钮就能继续。

## 1. 只检查相关环境

确认命令执行、项目文件、页面/构件创建、真实业务工具和文件交付方式；需要时查看 Python、Node、FFmpeg 等实际版本。读取现有项目说明与运行帮助，不扫描无关账户或凭据。

记录一个简单能力表：`页面 / 持久存储 / 云端动作 / 文件下载 / 外部访问`。缺少外部访问不妨碍先完成云内功能，但必须分别报告。

## 2. 创建小而完整的项目

使用独立工作目录；已有项目则先查看并保留。按案例默认数据创建第一版。将页面、实际处理程序、配置和结果分开保存。

原生构件接口可用时优先接原生动作。不可用时，可用当前环境支持的普通 Web 服务实现，并按真实方式交付可访问入口；不要把浏览器单页示意说成已经接通后台。

默认只实现本案例的核心流程。先让一条任务成功，再加批量、定时和分享；不要为了界面完整而制造成功数据。

## 3. 接好真实动作

页面提交参数 → 后台/Muse 动作验证输入 → 执行业务 → 写入结果和状态 → 页面读取结果。

耗时任务保存任务标识和状态，提供可理解的运行反馈。响应丢失先查询原任务；重试不应重复生成视频、重复加购或重复发布。单次动作失败，保留已完成结果与具体原因。

支持的操作直接执行；暂不支持的按钮禁用并说明。尽量用平台提供的秘密配置方式保存凭据，不把令牌写进页面源码或公开链接。

## 4. 保存与再次打开

保存用户输入、项目选择和产物清单。刷新页面、重新打开项目后检查记录仍在。不要通过刻意中断正在生成或改购物车的任务来测试恢复。

记录服务如何启动、停止和恢复，以及数据目录。云内地址不能直接当作对外地址；建立平台实际支持的网络入口后再测跨设备访问。对他人开放只分享必要功能，并配置权限，不分享整个 Muse 账号。

## 5. 用本案例样例验收

先跑默认小样，再改一个输入条件验证。视频检查真实媒体；精选检查原来源；购物核对真实页面；部署检查目标环境与实际入口。

下载按钮要在用户实际客户端试用。若文件已生成而按钮不能下载，通过受支持的附件方式交付真实文件，把按钮问题单独列出。

## 6. 交付

按 [验收模板](ACCEPTANCE.md) 用短句汇报。给一个真正可用的入口和一句用法，再列仍需登录/额度/网络的事项。若只能交付本地版本，明确其运行位置。

本仓库的文档和样例可以公开；用户运行后的项目记录、视频、账号和购物数据默认留在其私人工作区。
